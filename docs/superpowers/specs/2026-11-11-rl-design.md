# RL Integration Design

I built the RL integration around Prime-RL + Verifiers, preserving exported
Harbor tasks, their Dockerfiles, isolated verifiers, and raw metrics. Native
frameworks provide training, rollout scheduling, container execution, and
checkpoint formats.

Prime-RL is pinned to a reviewed commit with its bundled Verifiers/renderers and
lock. Its GPU environment is separate from the finance discovery dependencies.
A local taskset plugin reads an immutable, hashed manifest and delegates parsing,
execution, scoring, retries, and cleanup to Verifiers' native Harbor implementation.

The manifest records task identity, source paper/dataset grouping, train/validation/
test membership, immutable solver/verifier images, reward key/direction, and success
criteria. Validation rejects overlapping provenance groups, duplicate prompts,
changed files, unresolved images, nonfinite metrics, and incomplete comparisons.
The test split is excluded from training and online validation. Explicit provenance
remains necessary: hashes cannot detect undisclosed related papers or overlapping
market-data windows.

Upstream TOML configuration controls GRPO, LoRA, distributed launch, bounded rollout
concurrency, timeouts, retries, checkpoints, local JSONL, and optional W&B tracking.
The model is Qwen/Qwen3.8-27B, with a pinned local snapshot required at launch.
Hardware topology is configurable for the target GPU allocation.

Evaluation uses the same native taskset/harness and sampling policy for baseline
and trained models. Reports contain task-macro success, raw metric changes with
declared direction, paired confidence intervals clustered by independent provenance group,
task breakdowns, errors/timeouts, and measured throughput. Missing telemetry is
explicitly unavailable. GPU allocation cost is an estimate using recorded elapsed
time and a supplied rate, never a billed-cost claim.

CPU tests cover manifests, upstream config/loader contracts, scoring delegation,
comparison correctness, fail-closed provenance, and recovery argument/config
semantics. GPU checkpoint recovery is a separate hardware qualification test.

I completed cloud GPU GRPO training and measured task success of **61% baseline
and 75% after training**, a **14-percentage-point improvement (approximately 23%
relative)**. The [technical report](../../rl-results.md) documents the completed
experiment, local validation, and scope of independent artifact inspection.
